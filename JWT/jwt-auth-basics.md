# JWT - 로그인 상태를 서버가 저장하지 않는 방법
세션 없이도 "이 사람이 로그인했다"는 걸 증명할 수 있다. | 2026-05-13

### 개념
JWT(Json Web Token)는 사용자 정보를 토큰 안에 직접 담아서 주고받는 인증 방식이다.<br/>
서버가 세션을 DB에 저장할 필요없이, 토큰만 검증하면 누군지 알 수 있다. API 서버, 모바일 앱, MSA 환경에서 사실상 표준으로 쓰인다.

JWT 구조 - 점(.)으로 구분된 3부분
`헤더`.`페이로드`.`서명`
**헤더** - 토큰 타입(JWT), 암호화 알고리즘(HS256 등)<br/>
**페이로드** - 실제 데이터 (user_id, role, 만료시간 등). Base64 인코딩 -> 누구나 디코딩 가능<br/>
**서명** - 헤더+페이로드를 서버의 비밀키로 서명. 위변조 감지.

로그인 흐름
```
1. 클라이언트가 아이디/비밀번호로 로그인 요청
2. 서버가 검증 후 JWT 발급
3. 클라이언트는 이후 요청마다 헤더에 토큰 첨부 / Authorization: Bearer <token>
4. 서버는 서명만 검증 → DB 조회 없이 인증 완료
```

> **페이로드는 암호화가 아니다.** Base64 인코딩이라 누구나 디코딩할 수 있다. 비밀번호, 카드번호 같은 민감한 정보는 절대 넣지 말 것. user_id, role 정도만!<br/>
> **JWT는 강제 로그아웃이 어렵다.** 토큰이 만료되기 전까지 서버가 막을 방법이 없다. 로그아웃 기능이 중요하다면 Redis에 블랙리스트를 관리하는 방식을 쓴다.
