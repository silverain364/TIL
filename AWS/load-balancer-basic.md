# 로드 밸런서 - 트래픽을 여러 서버에 나눠주기
서버 한 대가 버티지 못할 때, 여러 대로 나눠서 받는 구조 | 2026-07-08

### 개념
로드 밸런서는 클라이언트 요청을 여러 서버에 분산시키는 장치다. 서버 한 대가 다운돼도 다른 서버로 요청을 보내 서비스가 유지된다.<br/>
트래픽이 늘어나면 서버를 추가하는 것만으로도 처리량을 늘릴 수 있다. AWS에서는 ALB(Application Load Balacer)가 대표적이다.

### 분산 알고리즘
`Round Robin` : 순서대로 돌아가며 배분. 가장 기본이며 서버 사양이 동일할 때 사용된다.</br>
`Least Connection` : 현재 연결 수가 가장 적은 서버로 요청 처리 시간이 다를 때 유리하다.</br>
`IP Hash` : 클라이언트 IP 기반으로 항상 같은 서버로 세션 유지가 필요할 떄 사용된다.<br/><br/>

> *로드 밸런서 쓰면 세션 주의* - 로그인 세션을 서버 메모리에 저장하면 다른 서버로 요청이 가는 순간 로그인이 풀린다. Redis에 세션을 저장해야 어떤 서버로 가도 문제없다.
</br>
> *스케일 업과 스테일 아웃의 차이점* - 서버 사양을 높이는 게 스케일 업, 서버 대수를 늘리는 게 스케일 아웃, 로드 밸런서는 스케일 아웃을 가능하게 하는 핵심 인프라다.
