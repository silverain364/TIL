# 로깅 - print()는 개발용, 운영 서버엔 logger를 써라.
장애가 났을 때 로그가 없으면 원인을 찾을 방법이 없다. | 2026-07-21

### 개념
로깅은 서버에서 일어나는 일을 기록하는 것이다. print()는 콘솔에만 찍히고 사라지지만, 로거는 파일 및 외부 시스템에 저장하고 레벨별 필터링이 가능하다.</br>
운영 서버에서 장애가 나면 로그가 유일한 단서다. 처음부터 제대로 찍는 습관이 중요하다.

### 로그 레벨
`DEBUG` - 개발 중 디버깅용. 운영에선 끄는 게 기본.</br>
`INFO` - 정상 동작 기록. "유저 로그인", "주문 생성" 등</br>
`WARNING` - 잠재적 문제. 당장은 괜찮지만 주의가 필요한 상황.</br>
`ERROR` - 오류 발생. 즉시 확인 필요. 예외 처리 실패 등.</br>
`CRITICAL` - 서비스 중단 수준의 심각한 오류, 즉시 대응.

### print() VS logging
print - 운영에 쓰이면 안 됨
```
print("유저 로그인:", user_id)
print("에러 발생!")
# 레벨 없음, 파일 저장 안 됨
# 타임스탬프 없음
```
logging - 운영 표준
```
logger.info("유저 로그인: %s", user_id)
logger.error("에러 발생", exc_info=True)
# 레벨, 시간, 파일명 자동 포함
# 파일/외부 시스템에 저장 가능
```

>*exc_info=True 습관화 해야한다.* ERROR 레벨에는 항상 exc_info=True를 붙이자. 스택 트레이스(어디서 터졌는지 전체 경로)가 같이 찍혀서 디버깅 시간이 확 줄어든다.</br>

>*로그에 비밀번호 및 카드번호 절대 금지.* 로그 파일은 여러 사람이 볼 수 있다. 민감 정보는 마스킹하거나 아예 찍지 말 것. password=**** 처리가 기본이다.
