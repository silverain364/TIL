# SQL JOIN - 테이블을 엮는 방법
JOIN을 모르면 테이블이 쪼개진 이유가 없다. | 2026-06-09

### 개념
관계형 DB는 데이터를 여러 테이블에 나눠 저장한다. users 테이블과 orders 테이블이 따로 있을 떄,<br/>
JOIN으로 연결해서 "누가 무엇을 주문했는지" 한 번에 조회할 수가 있다. JOIN의 종류에 따라 어떤 행이 결과에 포함되는지 달라진다.

### JOIN 종류 한눈에
`INNER JOIN` : 양쪽 테이블 모두에 매칭되는 행만 반환. 가장 많이 쓴다.
→ 주문이 있는 유저만 조회

`LEFT JOIN` : 왼쪽 테이블은 전부, 오른쪽은 매칭되면 포함 (없으면 NULL).
→ 주문 없는 유저도 포함해서 조회

`RIGHT JOIN` : 오른쪽 테이블은 전부, 왼쪽은 매칭되면 포함. LEFT JOIN으로 대체 가능.
→ 실무에서 거의 LEFT JOIN으로 씀.

`FULL OUTER JOIN` : 양쪽 테이블 모두 포함, 매치 안 되면 NULL. MYSQL은 미지원.
→ 양쪽에서 매칭 안 된 것도 전부 보고 싶을 떄

> **LEFT JOIN + WHERE IS NULL 패턴**은 실무에서 자주 쓰인다. "아직 주문 안 한 유저", "댓글 없는 게시글" 같이 한쪽에만 있는 데이터를 찾을 떄 유용하다.<br/>
> **JOIN이 많아질수록 느려진다.** JOIN하는 컬럼(FK)에 인덱스가 없으면 Full Scan이 일어난다. Day 3에서 배운 인덱스와 세트로 기억해두자.
